# 07_CONVERSION_ARCHITECTURE

## Purpose

This folder defines how the Atrellis website is structured to convert visitors into qualified action.

Its role is to explain:
- how conversion should work across the site,
- how trust, relevance, and action connect,
- what pages perform which conversion roles,
- and how the website should turn broad attention into structured leads.

This folder is important because conversion is not just about forms or buttons.
It is about how the entire site works together.

## What belongs here

- Conversion logic across the website
- Conversion stage mapping
- Page-role contribution to conversion
- Trust-to-action system design
- Qualification and friction principles
- Strategic conversion sequencing

## What does not belong here

- CRM implementation details
- Deep ad-funnel analysis
- Full analytics reporting
- Isolated CTA copy lists
- Raw wireframes with no conversion interpretation

Those belong elsewhere.

The main source of truth is:

## Usage rules

- Conversion should feel guided, not forced.
- Not every page should push for immediate inquiry.
- Trust and relevance should support conversion before friction is introduced.
- The site should convert both direct-intent and slower-evaluating visitors.
