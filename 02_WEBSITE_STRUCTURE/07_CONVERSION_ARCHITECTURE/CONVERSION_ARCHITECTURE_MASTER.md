# Conversion Architecture Master

## Core principle

Atrellis should convert by increasing clarity, relevance, and trust before asking for meaningful commitment.

The site should feel like a better-organized path forward, not a pushy sales funnel.

## Main conversion model

The Atrellis website should move users through this progression:

attention -> understanding -> relevance -> trust -> confidence -> action

Not every visitor starts at the same point.
Some arrive ready to act.
Others need more reassurance first.

## What the site should convert toward

The main conversion outcomes are:

- direct inquiry
- scoped project discussion
- category-specific interest
- future quote or guided-flow participation
- future gated value exchange

## Conversion architecture rule

The site should support both:

### 1. Fast-path conversion
For users with strong intent who want to move quickly.

### 2. Confidence-path conversion
For users who need more proof, explanation, and reassurance before acting.

Both paths should feel natural.

## Why this matters

In Atrellis' category, many users hesitate because:
- trust is low
- providers look similar
- service scope feels unclear
- next steps often feel vague

A better conversion architecture solves part of the category problem itself.

## Strategic rule

Conversion should be distributed across the site.

It should not depend only on:
- one contact page
- one hero button
- or one hard-sell section

Instead, the website should create multiple confidence-building entry points into action.
