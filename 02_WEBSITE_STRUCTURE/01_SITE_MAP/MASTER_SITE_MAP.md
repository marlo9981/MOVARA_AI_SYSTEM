# Master Site Map

## Purpose

This file defines the main website structure for Atrellis.

The website should feel broad but controlled.
It must support conversion, authority, and future growth without overwhelming users.

## Primary public pages

### 1. Home
Purpose:
- create first impression
- establish trust
- explain brand value quickly
- guide users into the right next step

### 2. Services
Purpose:
- present the broad Atrellis offer clearly
- group services in a way that feels structured
- help users move into the right category or inquiry path

### 3. Products / Systems
Purpose:
- present product-system-led categories in a clearer and more specific way
- support users arriving with product-specific intent
- create stronger category authority

### 4. Projects / Blog
Purpose:
- display work, authority, references, and content
- build confidence through examples and knowledge
- support SEO and AIO content visibility

### 5. About / Partners / Sponsors
Purpose:
- explain who Atrellis is
- strengthen trust and authority
- show ecosystem credibility

### 6. Contact / Inquiry
Purpose:
- convert interest into action
- support direct inquiry
- create a clear next-step path

## Supporting page groups

### Service-category pages
These pages support deeper service explanation and search intent.

Examples:
- zipblinds
- roofing systems
- balcony works
- waterproofing
- blinds
- full-home renovation

### Content pages
These support search, answer visibility, authority building, and user education.

Examples:
- blog articles
- FAQs
- comparisons
- educational guides
- category-specific advice pages

### Trust-support pages
These reinforce credibility and reassurance.

Examples:
- process-related content
- partner/supplier ecosystem pages
- about/team narratives
- proof-oriented pages

## Structural rule

The top-level site should stay simple.

Not every useful content type should become a top-level navigation item.

Use a small number of top-level pages and allow depth through internal linking and supporting pages.

## Recommended public site map

- Home
- Services
- Products / Systems
- Projects / Blog
- About
- Contact

## Future-ready route thinking

The structure should allow future expansion into:
- configurators
- guided quote flows
- visualization flows
- gated outputs
- lead dashboards
- customer portal logic

These do not all need to be public top-level pages now, but the site map should not block them later.
