# Superseded Decisions

## Purpose

This file records decisions that were once active but have been replaced, reversed, or rendered irrelevant.

Keeping superseded decisions here (instead of deleting them) preserves the reasoning history and prevents the same debates from recurring.

## Superseded entries

### 000 — Initial filing structure approach
- **Original date:** 2026-04-05 (early session)
- **Superseded date:** 2026-04-05
- **Original decision:** Generate full content for all folders immediately
- **What replaced it:** Blank scaffolding first, then incremental content population guided by the user
- **Reason for change:** User explicitly rejected full content generation. The correct approach is to establish structural skeleton first, then populate content folder by folder under direct user control.
- **Lesson:** Structure before content. Let the user dictate content pace and direction.

## How to add a superseded decision

1. Copy the original decision entry from `DECISION_LOG_MASTER.md`
2. Add the superseded date and what replaced it
3. Add a brief reason for the change
4. Remove the entry from `DECISION_LOG_MASTER.md`
