# Page Hierarchy

## Top-level pages

These are the main pages users should recognize quickly:

- Home
- Services
- Products / Systems
- Projects / Blog
- About
- Contact

These should carry most of the main navigation weight.

## Second-level pages

These pages sit under top-level groups and support more specific intent.

### Under Services
- service category pages
- service overview pages
- specific solution pages

### Under Products / Systems
- product-type pages
- comparison pages
- category-specific education pages

### Under Projects / Blog
- project case pages
- article pages
- authority content pages

### Under About
- company story
- partner/supplier ecosystem
- process or trust-related subpages if needed

### Under Contact
- inquiry path variations
- quote request path
- consultation path if separated later

## Third-level depth

Third-level pages should exist only when they clearly help:
- SEO intent capture
- user clarity
- category explanation
- or future product logic

Do not create unnecessary page depth just to look comprehensive.

## Hierarchy rule

A user should understand the top-level structure in seconds.

Depth should help relevance, not create complexity.

## Content relationship rule

Page hierarchy should support:
- user navigation,
- content discovery,
- conversion,
- and future route scalability.
