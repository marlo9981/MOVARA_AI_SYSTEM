# Future Route Expansion

## Purpose

This file explains how the public website structure can expand later without needing a full rewrite.

## Why this matters

Atrellis is not only building a website.
It is building a structure that may later support richer digital experiences.

That means route thinking should be future-aware.

## Likely future route groups

### 1. Configurator-related routes
Possible examples:
- product selection flows
- guided system configuration
- category-specific interactive routes

### 2. Quote-related routes
Possible examples:
- quote request flows
- scoped inquiry routes
- gated output experiences

### 3. Visualization-related routes
Possible examples:
- floorplan-to-render workflows
- gallery-to-concept routes
- visual guidance paths

### 4. User-specific flows
Possible examples:
- saved inquiry state
- customer portal areas
- lead follow-up pages
- internal dashboard routes later

## Expansion rule

Future expansion should feel like a natural extension of the current site, not a separate disconnected product.

## Public rule

Do not expose complex future routes too early if they are not ready.

Instead:
- design the structure to allow them,
- keep internal planning clear,
- and activate them when they create real value.

## Technical implication

The future route system should be anticipated in:
- site structure
- page relationships
- build-system planning
- content model design
